# 검증 기록

검증일: 2026-11-04. Python 3.12.14, Windows 환경에서 측정 모듈 43개와 백엔드 전체 및 등록 통합 테스트를 확인했습니다. GitHub CI에서도 Python 3.11/3.12로 측정 모듈과 백엔드 연동을 검사합니다.

## 확인한 동작

- 알려진 보드 투영 좌표에서 0.60 × 0.45 × 0.75m 직사각형과 ENU 바닥 배치점 복원
- 최고점 추가 촬영으로 전체 높이 1.30m 계산 및 사용자 실측 높이 입력
- 원·타원·오목 다각형의 형상 계산과 자기 교차 다각형 거절
- 단계별 사진의 지점 ID 자동 연결과 특정 지점 재촬영
- 누락된 카메라 정보, 왜곡 정보 미지정 raw 입력, 중복 보드 ID, 부족한 표본 거절
- 지점별 반복 편차 초과, 서로 모순되는 바닥/ENU 기준과 변환 행렬 거절
- 높이 기준만 있을 때 ENU를 생성하지 않음
- 여러 가구의 공통 좌표계 통합 및 공간 ID·중복 가구 ID 확인
- 실제 PNG 디코딩·마커 검출 및 이미지 크기 불일치 거절
- HTTP 계획 생성 → 측정 → Scene → 별도 버전의 fragment 출력·검증
- 기준 마커 중심 좌표와 ENU 좌표의 변환 일관성
- 장면·fragment의 중심·yaw 재계산과 클라이언트 임의 필드 차단
- 캡처 시점 티켓으로 지점 고정, 다음 지점으로 넘어간 뒤의 지연 응답·재촬영 이전 응답 거절
- fragment ID 정규화·원래 ID 매핑, component별 derived field 경로 검증
- 공개 JSON Schema·OpenAPI와 실행 모델의 일치
- 측정점·높이 모드와 다른 치수 거절, 같은 공간 ID의 다른 ENU 변환/바닥 기준 거절
- 저장된 보정 ID·기준 마커 변환 대조, 미등록/다른 보정의 가구 추가 무변경 거절

fragment는 `sunsync.fr06-fragment/1` 전송 봉투이며, 백엔드에 일반 3D 관측 타입과 `/api/scenes/{scene_id}/registrations` 등록 경로를 추가했습니다. 합성 사진 코너 관측 → PnP 측정 → fragment → 실제 FastAPI 등록 → SQLite 저장 → 조회 → 전체 Scene 및 JSON Schema 검증을 통합 테스트합니다. 상판 높이·최고점·수동 높이·설치 높이, 여러 가구의 보드 재사용, revision 충돌, 시각 누락·형상/좌표/치수 불일치 시 무변경 거절을 확인합니다. 기존 바닥 평면 관측의 제한은 유지합니다.

합성 입력은 실제 사진에서의 오차를 입증하지 않습니다. 기존 수평 이동 실측 109cm에 대한 추정 97.4cm, 오차 약 10.6%는 별도 실제 실험 결과입니다. 새 서비스 패키지의 기기별 정확도는 아직 평가하지 않았습니다.

HTTP 테스트 도구의 Starlette/HTTPX deprecation 경고 1건은 남아 있으며 테스트 실패는 없습니다. 실제 배포에 사용하는 의존성 버전은 팀에서 고정·업데이트해야 합니다.

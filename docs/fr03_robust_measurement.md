# 관측 선별과 도형 공동 최적화

## 적용 범위

단일 60cm ArUco 마커와 기존 필름 행·열/ENU 계약을 유지한다. `/v1/measurements`의 기본 `estimation_mode`는 `robust_joint`다. 비교 실험에는 `legacy`(중앙값·기존 형상 적합), `weighted`(관측 선별·불확실성 가중 통합)를 지정할 수 있다. 최종 치수는 실측 정답을 입력받지 않고 계산한다.

## 관측 처리

1. 기존 마커 ID·픽셀·자세 모호성·재투영 오차 검사를 적용한다.
2. 투영 Jacobian과 최소 0.5px의 관측 잡음으로 자세 공분산을 추정하고, 알려진 카메라→측정 지점 오프셋까지 전파한다. 선형화가 불안정하거나 지점 불확실성이 기본 0.15m를 초과하면 거절한다.
3. 동일 이미지 해시를 제외한다. 중앙값 거리와 MAD를 사용하되 반복 편차 상한(기본 3cm) 안에서 엄격한 과반수 및 필요한 관측 수가 남아야 한다. 정상 관측이 부족하면 결과를 만들지 않는다.
4. 낮은 공분산과 서로 다른 관측을 우선해 기본 최대 8개를 선택한다. 픽셀 배치가 거의 같은 관측은 묶어 가중치를 나누며, 반복 장수만으로 공분산이 0에 가까워지지 않게 한다.
5. 보정된 원본 코너 픽셀, 관측별 카메라 자세, 지점 위치, 선택 도형의 조건을 함께 최적화한다. 손 배치 오차는 기본 1cm의 잔차 항으로 허용하며 렌즈가 모든 지점에 완벽히 일치한다고 가정하지 않는다. 직사각형은 직각·평행, 원/타원은 곡선, 다각형은 수평 평면과 꼭짓점 순서를 사용한다. 스케치 비율은 측정값으로 사용하지 않는다.
6. 수렴 실패, 과도한 지점 보정, 큰 재투영 오차, 비정상 형상을 거절한다. 기존 높이·ENU·FR06 재검증을 그대로 거친다.

최적화는 SciPy `least_squares`의 soft-L1 손실과 희소 Jacobian 구조를 사용한다. 지점당 최대 20개 원본, 선택 최대 12개, 최대 120회 함수 평가로 계산을 제한한다. 모든 입력 형상의 정확도 향상을 보장하는 알고리즘은 아니다.

`points`에는 원본/유효/선택 수, 선택 ID, 가중치, 반복 편차, 공분산과 조건부 불확실성이 담긴다. 공동 최적화 전 좌표는 `raw_point_board_m`, 최종 좌표는 `point_board_m`이며 `optimization`에 비용·보정량·재투영 잔차를 기록한다. `capture_diagnostics.selected`로 실제 채택 여부를 확인한다. 이 불확실성은 보정값·마커 실측 크기·사용자 위치 편향의 오차를 포함하는 정확도 보증이 아니므로 FR06의 실측 정확도 필드를 채우지 않는다.

## 한 번 눌러 촬영

현재 모바일 웹 테스트 화면에서 연사 모드를 선택하면 카메라 스트림을 열고 그 스트림의 별도 카메라 준비를 수행한다. 사진 모드 보정값을 재사용하거나 덮어쓰지 않는다. 현재 지점에서 버튼 한 번으로 10프레임을 확보하고 밝기·선명도 및 서버 자세/반복 검사 후 채택한다. `/v1/observations/select`와 최종 측정은 같은 선별 규칙을 사용한다.

촬영 시각은 프레임을 캔버스에 복사하는 순간 기록한다. 이는 네이티브 센서 노출 시각과는 다르다. 셔터 시점의 지점 티켓을 유지하고 도형 변경·재촬영·화면 종료로 무효화된 결과는 버린다. 카메라 설정이 바뀌면 보정부터 다시 수행한다. 사진 파일 업로드는 파일 수정 시각을 사용하므로 실제 노출 시각 검증 자료로 사용하지 않는다.

보정 완료 후 미리보기에서 주기적으로 마커를 검사해 관측이 불안정하면 각도 조정을 안내한다. 이 미리보기는 네트워크 기반 테스트 경로이며 네이티브 앱의 실시간 프레임 분석 성능 검증을 대신하지 않는다. 네이티브 호스트 UI와 실제 기기 검증은 제외된 별도 작업이다.

## 자동 검증과 비교

고정된 별도 seed 800~819, 픽셀 잡음 0.3px, 지점 배치 잡음 2mm, 지점당 8개 관측으로 4개 도형을 비교한다. 이상치 조건은 지점마다 1개 관측을 9cm 이동한다. 정답은 출력 평가에만 사용하며 추정 입력에 포함하지 않는다.

실행:

```sh
python measure/registration-core/tools/run_robust_benchmark.py --output benchmark.json
python measure/registration-core/tools/compare_measurement_modes.py request_json_folder --truth dimensions.json --output comparison.json
```

`dimensions.json`은 파일명→`[가로, 세로, 높이]`(m) 대응이다. 모든 입력의 성공·거절 수를 함께 기록하며 잘 맞는 조합만 선택하지 않는다. 저장소의 `measure/registration-core/examples/robust-benchmark.json`은 합성 결과 요약이다.

잡음만 있는 직사각형 20세트의 평균 절대 오차(가로/세로)는 중앙값 0.125/0.080cm, 가중 통합 0.105/0.067cm, 공동 최적화 0.095/0.061cm였다. 이상치 조건에서는 기존 방식이 20세트 모두 거절했고 두 새 방식은 정상 다수 관측을 선별했다. 타원·다각형의 일부 축은 공동 최적화가 가중 통합보다 소폭 나빠졌으므로 일률적인 성능 향상으로 해석하지 않는다. 합성 데이터 수치는 실제 휴대폰의 5% 정확도 달성 근거가 아니다.

## 남은 실제 실행 확인

- 테스트 서버에 변경을 반영하고 카메라 권한·스트림 보정·연사·재촬영을 확인한다.
- 같은 실물 가구의 요청 데이터를 보관하고 세 방식의 성공률·치수/위치 오차·소요 시간을 비교한다.
- 여러 거리·각도·사용자·도형에서 실측 대비 오차를 확인한다.
- 촬영 결과가 저장·PC 도면·3D에 일치하는지 확인한다.

실제 필름의 반사·대비·물리적 표시 검증은 요구 범위에서 제외한다.

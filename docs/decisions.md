# Decisions

One line per decision. Add a row when the team makes a decision that affects scope, design or numbering.

| Date | Decision | Why | Trade-off |
|---|---|---|---|
| 2026-10-14 | Backend FastAPI, DB SQLite + SQLModel, Frontend React + Vite | Calculation libraries are Python; zero-install DB | SQLite is weak for concurrent writes; move to PostgreSQL if deployed |
| 2026-10-14 | Software only: no physical film, sensors or appliance control | Schedule and budget | No hardware demonstration |
| 2026-10-14 | Meeting notes are kept in the shared Google document; all other documents (requirements, API, data, decisions, reports) live in `docs/`; the GitHub wiki is not used | One place per kind of document; `docs/` changes are reviewed with the code | Meeting notes have no history in the repository |
| 2026-10-15 | Space model uses ENU coordinates (x east, y north, z up, metres) with Scene v0.2.0 | Common format for prediction, measurement and UI (PR #1) | Every module must convert to ENU |
| 2026-10-21 | Protection grades A-D follow the PR #1 definition | Already implemented and tested | Grades B and C need an intensity estimate |
| 2026-10-21 | The film is a virtual device with fine-grained, independently switchable cells | Hardware specifications are not public | Hardware feasibility is not verified |
| 2026-10-21 | Without weather forecasts, sunlight intensity is estimated under clear-sky conditions | Works without external data | May shade unnecessarily on cloudy days |
| 2026-10-21 | Spatial measurement: the marker shown on the window film is photographed once from each of the four corners of a piece of furniture (no video, no VO/SLAM); the camera position from solvePnP is used as the corner, and photos without the whole marker are rejected | Agreed at the 10/21 meeting; simpler than video tracking and has no drift | Furniture height is entered manually; accuracy drops far from the window |
| 2026-10-21 | FR renumbering: FR-03 = QR measurement, FR-05 = film control interface; the former FR-03, FR-05, FR-07 and FR-08 are removed and will be added later with new numbers | Reflect new functions and keep this term's list to FR-01 to FR-06 | FR-03 means something different in older documents |
| 2026-10-21 | Main scenario is a library reading room; the space model stays general | Clearest motivation and evidence | Other spaces are not tested this term |
| 2026-10-21 | The film is modeled as PDLC by default: an opaque cell scatters direct sunlight into diffuse light; documents say "opaque", not "darken"; SPD is an alternative | PDLC is fast, clear when transparent and widely available | Opaque cells reduce the direct beam but not all light reaching the room |
| 2026-10-21 | A 1 m x 1 m window is divided into 10 x 10 cells of 10 cm | Fine enough to shade a single shelf and to show a marker | Real products offer only a few segments |
| 2026-10-31 | Protected regions are evaluated as 5 cm x 5 cm tiles represented by centre sample points. FR-01 returns each exposed tile's geometrically valid ENU window crossing as `candidate_path.window_id` and `candidate_path.window_hit_m`; FR-02.1 converts the crossing to window-local coordinates, expands it by 2.5 cm left/right/up/down, and activates every overlapping 10 cm x 10 cm film cell | The finer protected-region raster represents partial exposure more precisely than the film grid and keeps ray tracing and film-grid policy at a clear module boundary | Results are a 5 cm raster approximation: sub-tile exposure is not represented, and FR-01 does not return a film-cell index |
| 2026-10-21 | The marker on the film is an ArUco 4x4 marker (6 x 6 cells with border); the team keeps calling it the "QR marker" | The smallest QR code needs 21 x 21 cells and does not fit 10 x 10 | The marker carries only an ID |
| 2026-10-21 | Sunlight intensity uses Open-Meteo forecasts when available, with clear-sky values as the fallback | Weather changes intensity, which grades B and C depend on | Forecasts are model estimates, not on-site measurements |
| 2026-10-21 | FR-04 smooths the planned schedule (gap filling, minimum holding time, threshold margin for grades B and C, cell-edge margin) instead of reacting to passing clouds | Control is planned ahead at fixed time steps, so real-time cloud reactions do not apply | Some cells stay opaque slightly longer than needed |
| 2026-10-29 | FR-01.4 production DNI source is Open-Meteo only; worker-collected immutable hourly snapshots are selected per timestamp, with pvlib clear-sky fallback | Keeps API requests independent from provider availability and makes selected forecast input reproducible | Provider-grid DNI is regional forecast data, not a window or floor measurement. Details: `fr01_4_open_meteo_dni_design.md` |
| 2026-10-21 | All 36 issues were closed and will be recreated per sprint once owners are fixed; every issue uses the user-story format, and the story/task labels were removed | Scope and owners changed after the 10/21 meeting | Old issue numbers are not reused |
| 2026-10-21 | The requirement document (deliverable A) is stored as `docs/reports/SunSync_Requirements.pdf` | Keep the submitted version with the code | Edits are made in Word and the PDF is replaced by a new PR |
| 2026-10-21 | API paths use the `/api` prefix (for example `/api/scenes`); the `/api/v1` paths in the Google document are dropped | The implemented routes (PR #1, #2) already use `/api`, and the Google document disagrees | There is no version in the URL, so a breaking change later needs a new prefix |
| 2026-10-21 | Sprint 1 ends on 11/4 (MVP); after that the work is split into one-week sprints, four sprints in total (11/4, 11/11, 11/18, 11/25) | Short cycles give feedback before development ends on 11/30 | More frequent planning and review overhead |
| 2026-10-23 | Scene schema stays at v0.2.0 with optional defaults for window film grid (10x10, top-left origin), window marker placement (6x6 at (2,2)), occluder furniture type (other), and room floor_level | Additive optional fields preserve backward compatibility with existing v0.2.0 scenes and FR-01 | Consumers must apply defaults when optional fields are omitted in raw JSON |
| 2026-11-04 | FR-05 film control uses a REST API virtual film state machine with a hardware-agnostic opacity interface (0.0..1.0) covering PDLC and SPD | Zero-install development without MQTT broker dependencies, while JSON commands map 1:1 to MCU HTTP/MQTT payloads (#60) | Software simulation only; physical MCU requires HTTP polling or a bridge |
| 2026-11-04 | Infeasible shading plan segments set cell opacity to 1.0 (opaque) and record audit log status "target_unmet" with note "목표 미달"; simulation clock evaluates state at any timestamp | Maximizes protective shading while preserving traceability of unmet illumination constraints across the timeline (#61) | Cells stay opaque even when the target irradiance cap cannot be met |
| 2026-11-04 | Film states and append-only transition logs are persisted in SQLite (film_states, film_application_logs) with WAL concurrency and 30s busy timeout | Ensures state recovery across server restarts and supports concurrent multi-client access (#62) | Database file must be preserved across deployment restarts |
| 2026-11-04 | Multi-user PPT ArUco marker demo isolation scopes states strictly to (scene_id, window_id), provisions a default window if missing, and auto-clamps furniture into room boundaries | Prevents simultaneous classroom/demo presenters using code_id=0 from conflicting or crashing on out-of-bounds camera measurements | Furniture placed outside the room is relocated/scaled down to fit |
| 2026-11-04 | All film log and simulation clock timestamps are normalized to UTC ISO 8601 (YYYY-MM-DDTHH:MM:SSZ) on persistence and query, and marker-pairing synchronizes UISpaceRecord revision | Guarantees lexicographical SQLite query accuracy (<, <=, >, >=) across client timezones and avoids UI 409 revision conflicts | None; transparent to callers |
| 2026-11-04 | FR-01.4 AI enhancement pairs KMA 10-min point DSR/meteorology + optional 5x5 cloud patch stats with Open-Meteo hourly forecasts in a 2-stage Quantile Nowcaster (q10, q50, q90) recorded side-by-side in nowcast_point (migration v3) | Resolves the DSR != DNI conversion gap via Erbs physics decomposition + quantile regression while avoiding full 2D NetCDF ingest overhead and preserving automatic Open-Meteo / clear-sky fallback (#85, #86) | Requires KMA observation feed for live improvement; falls back to Open-Meteo uncertainty bands when KMA is absent |
| 2026-11-08 | FR-01.4 operational AI uses site-scoped worker snapshots and separate `ai_nowcast_*` tables; shadow is default, active serves frozen V1 at 10/30 min and Open-Meteo at 60 min | Keeps provider calls and training outside request handling, preserves frozen model hashes, and makes fallback/provenance auditable | Active rollout requires team review of shadow latency, fallback and error rates; missing Open-Meteo is explicitly unavailable |
| 2026-11-04 | FR-03 & FR-06 Vision AI pipeline calibrates monocular relative depth (Depth Anything V2 / MiDaS protocol) using metric anchor depths from the 6x6 window ArUco solvePnP pose (`d_metric = a * d_rel + b`) and back-projects 2D detections (YOLOv8 protocol) into floor-standing 3D Occluders | Eliminates walking to 4 corners per furniture item while solving monocular scale ambiguity through the existing 6x6 window film marker (#85, #87) | Self-occluded furniture thickness relies on class priors when viewed from a single angle |
| 2026-11-04 | FR-02 & FR-04 uncertainty-aware adaptive controller uses Viterbi dynamic programming over quantile irradiance (q10, q50, q90) with auto-tuned weights, supporting both binary PDLC and continuous LG SGF dimming via a ThinQ ON bridge | Optimizes the trade-off between artifact protection, daylight gain, and switching flicker on intermittent cloudy days (#85, #88) | Multi-step horizon optimization requires full-window forecast trajectories |

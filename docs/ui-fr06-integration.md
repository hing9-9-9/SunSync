# UI와 FR-06 저장 연동

`feature/ui-flow` 작업본에 로컬 main의 `ff9caf6`(FR-06 Scene 저장)을 fast-forward로 반영했다. 기존 UI 작업은 보존했다. 원본 체크아웃과 원격 저장소는 변경하지 않았다.

## 실행

프로젝트 루트에서 백엔드를 실행하고, 별도 터미널에서 프런트엔드를 실행한다.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

```sh
cd frontend
npm ci
npm run dev -- --host 0.0.0.0
```

브라우저는 http://localhost:5173/ 로 접속한다. Vite 개발/미리보기 서버가 `/api`를 8000번 백엔드로 전달한다. SQLite 파일 `sunsync.db`는 백엔드를 실행한 작업 디렉터리에 만들어진다. 실제 배포에서는 별도 API 라우팅 설정이 필요하다.

## 저장 흐름

- 내 공간을 열면 서버 목록을 조회한다. 기존 브라우저 전용 공간은 자동 업로드하지 않고 함께 유지한다.
- 공간 정보에 위도·경도·시간대와 북쪽 확인 여부를 입력한다. 위치를 임의로 채우지 않는다.
- 저장 시 UI 좌표의 아래 방향 y를 ENU 북쪽 방향 y로 변환한다. 가구는 직육면체, 보호면은 방향별 평면 다각형과 법선으로 저장한다. 가구 상단의 보호 높이는 가구 높이를 따른다.
- `/api/ui/spaces`의 POST/GET, `/{id}`의 GET/PUT이 UI 메타데이터와 공통 Scene을 같은 트랜잭션으로 저장한다. 건물·층·구역 등 UI 전용 정보는 별도 `ui_spaces` 테이블에 보관하여 기존 Scene 0.2.0 계약을 바꾸지 않는다.
- 서버 응답이 성공해야 저장 완료로 표시한다. 연결 실패와 입력 오류 때 편집 내용을 유지한다. 서버 버전이 다르면 409로 차단하고 최신 내용 불러오기를 제공한다.
- 공통 Scene API에서 다른 모듈이 수정한 데이터나 UI 메타데이터가 없는 Scene은 목록에서 별도 안내하고 자동 변환·덮어쓰기하지 않는다.
- 브라우저 저장소는 계정 데모·화면 캐시와 기존 로컬 공간 유지 용도다. 서버 저장 데이터는 같은 개발 서버에 접속한 웹/모바일에서 조회할 수 있다.

## 남은 연동 범위

(작성 당시 기준) Google 로그인, QR 측정, 예측·차광 시각은 데모였다. 이후 Google 로그인과 계정별 공간 분리는 구현되었고([auth.md](auth.md)), 측정과 예측의 현재 상태는 [ui-flow.md](ui-flow.md)의 "실제 동작과 데모 경계"를 본다. 예시 치수는 synthetic_fixture와 manual 출처로 기록하며 실제 ArUco 관측이라고 표시하지 않는다. UI 창 그림은 측정값이 없으므로 공통 Scene의 windows는 비워 둔다. 따라서 저장 성공이 실제 일조 계산 준비 완료를 의미하지 않는다. 창 실측·광학 프로필·구역 좌표 정합과 실제 엔진 연동이 남아 있다. A~D 설명은 유지하며 기술 정책의 예시 임계값은 확정 기준이 아니다. FR-03은 포함하지 않는다.

(작성 당시 기준) 백엔드에는 사용자별 권한 분리가 없었다. 2026-11-09부터 공간은 만든 계정의 것이며 다른 계정은 404를 받는다([auth.md](auth.md)).

## Limitations

- **Borrowed sky.** The direct irradiance was measured at a US station and is placed in the example Scene in Seoul by solar time (same month and day of 2026). The cloud pattern is real, but it is not Seoul's, and the Scene's geometry is Seoul's.
- **One Scene, one station, a few days.** The days are picked from the flicker statistics so that each kind is present; the result does not say how often such days occur.
- **Perfect forecast.** The measurement is used as if it had been forecast exactly. A real forecast is smoother and is revised over time; the revisions are not modelled.
- **One plan per day.** FR-04 smooths a single plan; the replay does not re-plan every few minutes as a nowcast would.
- **Caps are demo values.** The Scene's protection policy is marked `synthetic_demo_not_agreed`; the caps decide where the plan reacts to the sky.
- **Chunks.** The application refuses a plan with more than about 200 steps for this Scene, so the 1-minute step is computed in chunks of up to 200 minutes and the counts are summed. A cell exposed across a chunk boundary counts as two exposures in both plans; the comparison between the plans is not affected by this.
- **Label.** The Scene only accepts the weather sources `synthetic`, `open_meteo` and `pvlib_clear_sky`; the measured values carry `synthetic`.

## Data handling and security

- **No network request.** The tool only reads the files in the directory it is given. The files are downloaded by hand from the addresses in the table above; compare their SHA-256 with the table.
- **Untrusted data.** The files are read as text and parsed as numbers; nothing in them is executed. They are public data and are not committed to the repository (their terms of use were not checked); only the hashes and the derived tables are.
- **No secrets, no personal data.** The tool sends nothing and holds no key. The KMA replay reads a local CSV only. These reports hold no server address and no key.

# SunSync 요구사항 보고서 한국어 요약

원문: [SunSync_Requirements.pdf](SunSync_Requirements.pdf) (영문, IEEE 형식). 이 문서는 팀 공유용 요약이며 원문과 다르면 원문이 기준이다.

**제목**: SunSync: 전환형 스마트 필름을 이용한 선제적 채광 제어

## 초록
- 문제: 직사광은 도서관 자료를 손상시키지만, 블라인드를 내리면 열람실 전체가 어두워진다.
- 기존 한계: UV 필름과 동적 유리는 방 안 보호 대상의 위치를 보고 차광하지 않는다.
- 제안: 직사광이 들 곳을 예측해, 보호 대상에 닿을 빛이 지나는 필름 칸만 미리 불투명하게 한다.
- 사용 흐름: 앱에서 창에 띄운 QR 마커로 공간 측정 → 웹에서 보호영역과 등급 설정 → 서버가 태양 위치 계산, 직사광 경로 추적, 칸 상태 계획.
- 필름: 분할 PDLC·SPD 필름을 바탕으로 칸 격자로 모델링하고 소프트웨어로 시뮬레이션한다.
- 범위: 도서관 열람실이 주 시나리오, 박물관·쇼룸·가정으로 확장 가능.

## I. Introduction

### A. 동기
- 빛 손상은 누적되고 되돌릴 수 없다. 권고 기준은 연간 약 5만 lux·h이며, 직사광은 이를 금방 넘긴다.
- 도서관 이용자는 창과 채광을 선호해서, 서가가 큰 유리창 옆에 놓이기 쉽다.
- 기존 대책은 부분적이다.
  - UV 필름: 가시광은 통과시킨다.
  - 틴트 필름: 해가 없을 때도 항상 어둡다.
  - 블라인드: 서가 하나를 지키려고 창 전체를 가린다.
  - 동적 유리: 사람의 눈부심과 에너지가 중심이다.
- 구역 분할 필름과 태양 위치 계산은 이미 가능하다. 빠진 것은 "창의 어디를 언제 가릴지" 정하는 소프트웨어다.
- SunSync는 UV 필름과 함께 쓰며, 빛이 보호 대상에 닿을 칸만 불투명하게 한다.
- 공간 모델이 일반적이어서 다른 공간에도 그대로 적용된다.

### B. 문제
1. 사후 대응·수동 조작: 빛이 닿은 뒤에야 가리고, 센서와 고정 일정은 태양 경로를 따라가지 못한다.
2. 전부 아니면 전무: 서가 하나 때문에 창 전체나 큰 구역을 가려서 옆 좌석까지 어두워진다.
3. 보호 대상을 모름: 기존 시스템은 방 안 어디에 무엇이 있는지 모르니 선택적으로 가리지 못한다.

### C. 해결
1. 예측 경로 분석: 앞으로의 태양 위치로 보호면에서 창까지 직사광 경로를 미리 계산한다.
2. 칸 단위 선택 차광: 필요한 칸만 불투명하게 하고 나머지는 투명하게 둔다. 짧은 틈을 메우고 최소 유지 시간을 두어 잦은 전환을 막는다.
3. 보호 설정: 앱으로 측정하고, 웹에서 보호영역과 등급(엄격 차단부터 채광 우선까지)을 정하면 시스템이 시점과 범위를 결정한다.
- 필름 근거
  - PDLC: 빛을 흩뜨리고, 10~150 ms 만에 투명해지며, 투명할 때 투과율은 약 80%다.
  - SPD: 빛을 흡수해 최대 99% 막지만, 느리고 투명할 때도 옅은 색이 남는다.
  - 둘 다 몇 개 구역이나 띠 모양으로 나뉜 제품이 있다.
- 가정
  - 구역 분할을 작은 칸 격자로 확장한다. 이 프로젝트에서는 1 m × 1 m 창을 10 cm 칸 10 × 10개로 나눈다.
  - 기본은 PDLC다. 불투명 상태가 직사광을 확산광으로 바꿔 강한 햇빛 자국이 대상에 닿지 않는다.
  - 칸 격자 필름은 아직 팔지 않으므로 소프트웨어로 시뮬레이션한다.
  - 날씨 예보가 없으면 맑은 날 기준으로 세기를 추정한다.

### D. 관련 소프트웨어
1. 스마트 필름 (LG화학 SGF, 분할 필름 특허와 제품): 어느 구역을 바꿀지는 사용자가 정한다.
2. 동적 유리 (View, SageGlass): 미리 착색하지만 방 안 물건의 위치와 민감도는 고려하지 않는다.
3. 자동 차양 (MechoSystems SolarTrac): 차양 하나가 뒤쪽 전체에 같은 위치로 적용된다.
4. 스마트홈 (Google Home, Apple Home, LG ThinQ ON): 일정·기기 상태·사용 패턴 기반이다. SunSync가 Matter로 판단 결과를 넘겨줄 수 있다.
5. 태양 계산 도구 (pvlib, Radiance): 분석·설계용이다. SunSync는 pvlib로 태양 위치를 계산한다.

## II. Requirements

### A. 모바일 앱 (MAR)
- MAR1 로그인: Google 계정, 앱과 웹 같은 계정
- MAR2 공간 등록: 건물·층·공간 이름과 위치, 가로·세로·높이, 구역 나누기
- MAR3 QR 측정
  - 창 필름의 마커를 비추고 시작
  - 가구 네 모서리에 서서 각각 마커 사진 촬영 (마커가 다 안 보이면 재촬영 안내)
  - 서버로 전송하고 도면 생성 진행 표시
- MAR4 도면 확인: 저장, 웹 링크 열기, 재측정
- MAR5 공간 현황: 시간 슬라이더로 햇빛 자국, 보호영역 보기(편집은 웹), 필름 칸 상태 격자

### B. 웹 (WAR)
- WAR1 계정과 내 공간 목록
- WAR2 공간 등록, 앱 촬영 화면 링크 생성
- WAR3 편집
  - 가구 치수·위치 수정, 추가·삭제
  - 가구 선택 또는 영역 그리기로 보호영역 생성 (이름, 높이 범위, 등급 A~D)
  - 3D 보기: 가구 종류별 기본 모양, 끌어서 옮기기
  - 저장: 나가기 경고, 버전 충돌 경고
- WAR4 현황: 도면 또는 3D 개요, 보호영역별 차광 예정 시각과 재계산, 필름 칸 상태 격자

| FR-01 | 미래 햇빛 경로 예측 | 01.1 태양 위치 / 01.2 보호면에서 태양 쪽으로 광선 추적 / 01.3 시간별 노출 여부·이유, 첫 노출 시각 / 01.4 세기 (맑은 날 기준, Open-Meteo 등 예보로 교체) |
| FR-02 | 선택적 차광 결정 | 02.1 창 통과 지점 → 칸 / 02.2 등급별 결정 (겹치면 엄격한 쪽) / 02.3 전환 시간·지연·여유를 반영해 미리 차광 / 02.4 차광 일정을 앱·웹에 제공 |
| FR-03 | QR 기반 공간 측정 | 03.1 사진마다 마커 인식과 화질 확인 / 03.2 마커 크기와 네 꼭짓점으로 카메라 위치 계산 / 03.3 네 모서리 사진의 카메라 위치를 가구 모서리로 사용해 너비·깊이·창과 벽 기준 위치 출력 |
| FR-04 | 일시 변화에 안정적인 제어 | 04.1 짧은 틈 메우기 / 04.2 최소 유지 시간 / 04.3 B·C 등급 기준값 여유 / 04.4 칸 경계 여유 |
| FR-05 | 필름 제어 인터페이스 | 05.1 예정 시각에 칸 명령 적용·기록 / 05.2 측정 중 마커 표시 후 복원 / 05.3 하드웨어·필름 종류(PDLC, SPD)와 무관한 구조 |
| FR-06 | 공간 정보 관리 | 06.1 공간 모델 (가구 종류 포함) / 06.2 창과 마커 규격 / 06.3 측정 출처 / 06.4 검증과 버전 / 06.5 앱·웹 동기화 / 06.6 보호 등급 |

보호 등급 (FR-06.6)
| 등급 | 의미 |
|---|---|
| A | 모든 직사광 경로가 불투명 칸을 지나야 함. 예측 세기가 낮거나 알 수 없어도 적용 |
| B | 직사광 세기를 낮은 상한 이하로 제한 |
| C | 직사광 세기를 높은 상한 이하로 제한 |
| D | 채광 우선, 차광 요청 없음 |

### D. 비기능 (NFR)
- NFR1 정확성과 안정성
  - 1.1 첫 노출 시각이 손 계산과 한 시간 단계 이내로 일치, 입력에 단위·시간대·방향 기준 명시
  - 1.2 날씨 예보 변화 상황에서 안정화 전보다 전환 횟수가 적고 보호는 약해지지 않음
- NFR2 성능과 사용성
  - 2.1 구역 하나의 2시간 계획을 5초 이내 계산
  - 2.2 폰과 PC 화면 모두 지원, 단계마다 다음 할 일 안내
- NFR3 데이터 일관성: 한 기기에서 저장한 공간이 다른 기기에서도 같고, 같은 입력이면 같은 결과

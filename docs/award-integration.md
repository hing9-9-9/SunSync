# SunSync Award 예시 — 원본 기능 통합 대조표

## 접속과 구현 방식

- 웹(Award 디자인): `http://localhost:5173/?mode=web#/`. 웹 화면은 이제 Award 디자인만 씁니다. 통합 전 원본 웹 화면은 실행 경로가 없고 [원본 보관 자료](reference-original-2026-10-22/README.md)로만 남아 있습니다.
- 앱(휴대폰 화면): `http://localhost:5173/?mode=app#/`. `main.tsx`가 앱 모드(또는 좁은 화면)에서 `MobileApp.tsx`를 띄웁니다.
- 서버를 건드리지 않는 둘러보기: 웹 `?mode=web&example=editor`, 앱 `?mode=app&example=editor`. 예시 공간으로 편집기를 열고, 저장·위치·서버 목록·휴대폰 연결은 서버에 요청하지 않습니다.
- 이전 Reference 시안(`?example=reference`)은 없어졌고 `ReferencePreview.tsx`도 삭제했습니다. `ReferencePreview.css`는 App과 WorkspaceDesign이 계속 사용합니다.
- 앱 화면은 `AwardMobile.css`로 웹 Award와 같은 디자인 규칙을 따릅니다. 500 굵기 제목, 알약형 버튼, 얇은 테두리의 입력칸과 5px 카드, 4px 칩이 그 예입니다. 앱의 파스텔 그라데이션 배경, #6660e5, Noto Sans KR, 직각 도면은 그대로입니다.

`App.tsx`가 웹의 상태·검증·저장·탐색·측정 코드를 실행하고, AwardSystem은 머리글·랜딩·목록·가이드의 표현을 담당합니다.

새 예시에서 저장하면 원본과 같은 서버 공간에 반영됩니다. 수동 검증 중 작성한 임시 가구·구역·보호영역·등록 정보는 저장하지 않고 버렸습니다.

## 코드 대조

`node scripts/verify-award-parity.mjs`로 언제든 읽기 전용으로 다시 확인할 수 있습니다. 아래의 의도된 차이는 스크립트에 해시로 고정돼 있어서, 그 밖의 변경이나 고정된 부분의 추가 변경이 생기면 검사가 실패합니다.

| 대상 | 결과 | 비고 |
|---|---|---|
| 원본 App 함수 38개 | 35개 본문 동일, 1개 의도적 변경, 2개 의도적 제거 | 2026-10-23 기준 |
| 제거: `websiteNavigate` | AwardHeader의 `onNavigate`가 대신함 | 홈·가이드는 바로 이동, 내 공간·계정은 `requireAccount`로 로그인 확인 |
| 제거: `openWebsiteGuide` | AwardGuide가 단계 상태를 직접 가짐 | 머리글·랜딩에서 가이드 페이지로 이동 |
| 변경: `NumberField` | 숫자 칸 바로 아래 경고 | 입력하거나 칸을 벗어난 뒤 범위 밖이면 `aria-invalid`와 경고 문구 표시 |
| 핵심 18파일 | 16개 바이트 동일, 2개 의도적 변경 | core-integrity.json 기준 |
| 변경: `ShadingPlan.tsx` | 차단 시간 스위치 마크업 | 이름표(aria-label), 트랙, 켜짐/꺼짐 문구 |

이전 판 문서의 "37개 동일, 삭제 0개"는 그 뒤 수정으로 더 이상 맞지 않아 위 표로 바꿨습니다. `locateBuilding`, `refreshServer`, `transferSpace`, `save`, `saveShadingTime`은 웹 둘러보기 모드를 되살리면서 다시 원본과 같아졌습니다.

JSON의 originalLine은 보관한 App.original.tsx.txt의 행 번호입니다. 정적 코드 보존 외에 아래 흐름을 브라우저와 테스트로 확인했습니다.

## 디자인·사용 흐름

- 랜딩의 일러스트는 소개용이며 편집 화면에는 저장된 실제 2D 데이터를 표시합니다.
- 흰 배경·타이포그래피·선·절제된 보라색·전환 효과를 유지합니다.
- 도면 옆에 선택 설정, 상단에 편집 종료·저장을 배치합니다.
- 공간 검색·건물 필터를 추가하고 카드 최대 너비 270px을 유지합니다.
- 더보기에서 활성 보호영역만 집계하고 D는 제외합니다.
- 가이드는 독립 페이지를 유지하며 작업을 갑자기 실행하지 않습니다.
- 새 애니메이션 라이브러리를 추가하지 않았으며 reduced-motion을 존중합니다.

## 검증 범위

- 프런트 테스트 40개 통과.
- 백엔드 테스트 186개 통과. 격리 테스트 DB 사용.
- TypeScript·배포 빌드 통과. 린트 오류 없음. 원본 DeviceHandoff의 QR 상태 초기화 effect 경고 1건 유지.
- 수동 검증은 임시 작성 상태를 버렸고 기존 서버 공간을 수정·저장하지 않았습니다.
- 원본처럼 Google OAuth는 준비 중이며 체험 계정 흐름입니다.
- 실제 QR 자세 추정·치수 산출, FR01 실계산, 필름 하드웨어 제어를 새로 구현한 것은 아닙니다. 원본 사진 품질 검사·기본 치수 보정·간이 햇빛/필름 표시를 유지했습니다.
- 실제 카메라 촬영과 실물 필름 작동을 검증했다고 주장하지 않습니다. 촬영 UI 진입과 품질 검사 테스트까지 확인했습니다.
